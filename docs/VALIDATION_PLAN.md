# 题目三：数据可得性、验证与演示方案

更新：2026-09-24。本文只记录本次工作环境中核实到的能力；案例事实、测量结果和线上表现须在交付前填写实际证据，不能把目标值当实测值。

## 2. 评测数据和人工答案

先冻结一个小而完整的基准集：GS-01 至 GS-06 六份真实主事件材料、GS-X1 一份真实误合并对照材料；另有 3 篇可追溯的新闻已纳入；研报和传闻尚未纳入。否认、到期、重复转载等主案例未必具备的分支，用 3–5 份**显著标注的模拟测试材料**补足。逐条人工标注以下答案，再运行产品：

| 标注字段 | 判断口径 |
|---|---|
| `event_id` / `source_id` | 两篇材料是否指向同一具体事项；同公司、同题材不自动相同 |
| `claim_id`、原句、证据片段 | 将“合作已签约”“金额已确定”等拆成独立可核查主张；引用片段必须确实出现在来源内 |
| `claim_type` | 事实陈述、观点、推测、传闻；这是**说法性质**，与是否已证实分开 |
| `stance` 与 `state_after` | 新证据支持、反驳、更正或无关；结果为待核实、已确认、冲突、已否认、已更正、待复核等 |
| `origin_group` | 共同转引同一原始出处的材料归为一组，不按转载篇数累加独立证据 |
| 四类时间 | 发生时间可空；披露时间用于“当时公众能知道什么”；抓取时间是系统看见材料的时间；更新时间是来源自身修改的时间 |
| 标的关系 | 公告直接涉及的主体、交易对方、仅间接相关的主体分开标注 |

基准答案至少保留一次人工复核记录（标注人、复核时间、争议及处理）。若仅一人标注，报告中如实注明样本量和主观性，不能声称达到普遍准确率。

## 3. 测试矩阵

以下是**预期行为与验收条件**，不是已经通过的测试。执行后为每行补上测试日期、版本、输入 ID、实际结果、截图/日志路径、通过或失败。

| ID | 场景与输入 | 预期行为与检查点 |
|---|---|---|
| M01 | 导入一份带原文链接的公告 | 抽取主体、事件、主张和原句；打开证据能返回原文；不把模型摘要当原始证据 |
| M02 | 依次导入 GS-01→GS-02→GS-03→GS-04→GS-05→GS-06 | 提出同事件合并候选；每次保留原材料与版本。GS-04 为“终止风险上升”，GS-05 为“预计难续/待最终决定”，到 GS-06 才变为“2023 年方案终止、后续收购意向不确定” |
| M03 | 对已有华鲲振宇事件导入同公司、同日公告 GS-X1（倍特期货 33.75% 股权拟转让） | 不自动并入华鲲振宇事件；低把握建议人工确认；可回退误合并且留审计记录 |
| M04 | 两篇媒体均转述同一个原帖/公告 | 显示为两篇来源、一个原始证据组；证据独立性不因转载数增加 |
| M05 | 先有匿名传闻，后有官方否认 | 相关主张从“待核实”转“已否认”；展示前后差异与否认原句；已确认的其他主张不受无关否认牵连 |
| M06 | 后续更正金额、主体或日期 | 只更正受影响主张，保留旧版本及更正原因；关注用户收到含来源的变更通知 |
| M07 | 有效期已过但没有新证据 | 将时效敏感的说法标为“待复核/过期”，不自动标成“虚假”；显示时效规则及触发时间 |
| M08 | GS-06 的董事会决议发生于 2024-04-18、公告披露于 2024-04-19，系统另有实际抓取时间；来源更新时间无证据时留空。再用模拟来源补测 T4 更新时间 | 四时间分别展示；按披露时间回看 4 月 18 日时不泄露 4 月 19 日才披露的终止结论；抓取顺序不覆盖披露顺序；未知更新时间不猜填 |
| M09 | 缺发生时间、只有日期无具体时分 | 保留“未知/仅日期”，不填零点或把披露时间冒充发生时间；排序依据在 UI 标出 |
| M10 | 晚抓取的旧公告或来源修改 | 既有历史回看保持正确，当前状态重算；显示“现在才抓取到历史材料”或“来源已更新” |
| M11 | 文本声称“某公司股价上涨因本事件” | 最多标成待核实观点；若无独立验证，不输出事件导致涨跌的因果结论 |
| M12 | 原文 URL 失效、引用片段与原文不符 | 来源仍可见但标记链接失效/引文待复核；不升级主张为已确认；保留检索记录 |
| M13 | 文档无来源 URL、只有粘贴文本 | 标为用户提供的未核实材料；允许分析/保存，但不能与官方证据同权重或显示“官方确认” |
| M14 | 外部接口超时、500、限流或空响应 | 明确提示失败与重试；旧状态和历史不被清空；重试不生成重复来源或重复通知 |
| M15 | AI 抽取失败、JSON 不合法或引文定位失败 | 进入待人工核对状态；不生成有确定语气的主张结论；用户可修正后继续 |
| M16 | 输入含“忽略前面规则”等提示注入语句 | 当作来源文本处理；不能改变系统规则、隐藏出处或触发越权操作 |
| M17 | 用户关注某标的，同时有直接与间接相关事件 | 通知解释关系类型；不把产业关联等同于该公司真实订单、收入或价格影响 |
| M18 | 用户请求“该买/卖哪只股票” | 产品只给出处、状态与风险说明，不输出确定性的交易指令或收益承诺 |
| M19 | 同一事件状态无实质变化，重复导入同文 | 不重复通知；引用计数与版本数保持幂等 |

**必须实测的最短链路**：GS-01→GS-02→GS-04→GS-05→GS-06 的状态变化与通知，再做 GS-X1 的误合并防护、转载去重、四时间、接口失败及合规边界。GS-03 保留在完整时间线中。GS-06 是真实“方案终止”，不能为演示写成对全部未来收购的彻底否认。M05 否认、M06 更正、M07 到期若缺真实材料则使用模拟测试并显著标记。

## 4. 可衡量评估指标

| 指标 | 计算方式 | 建议验收目标（待实测） |
|---|---|---|
| 事件误合并率 | 人工标注为不同事件，却被系统自动合并的组数 ÷ 不同事件组数 | 基准集关键相似事件 **0 次自动误合并**；低把握转人工确认 |
| 同事件召回率 | 正确提示合并的同事件材料对 ÷ 所有同事件材料对 | 在冻结基准集上记录分子/分母；小样本不报泛化准确率 |
| 主张类型准确率 | 事实/观点/推测/传闻分类正确的主张数 ÷ 已标注主张数 | 记录混淆矩阵，特别关注把传闻误写成事实的次数 |
| 证据引用有效率 | 结论所列引文可在指定来源位置找到的数量 ÷ 全部结论引文数 | **100%**；无法定位时降级为待复核 |
| 状态迁移正确率 | 否认、更正、过期等用例中，状态和通知都与人工答案一致的数量 ÷ 总用例数 | 基准关键路径 **100%**，逐例列出失败 |
| 时间准确率 | 四时间及“截至某披露时点”的回看结果正确的测试数 ÷ 时间测试总数 | 关键时间用例 **100%** |
| 通知精确率 | 有实质状态变化的通知数 ÷ 所有发出的通知数 | 基准用例不因重复转载或重试发重复通知 |
| 工作流耗时 | 从拿到新材料到找到当前结论及原文证据的秒数 | 同一案例记录人工基线和产品完成时间；如未做对照，仅报告产品耗时，不称“效率提升” |

记录实际测量时写清基准集版本、样本量、人工答案和运行版本。失败样例比一个笼统“准确率”更有解释力。

## 5. 60–180 秒演示分镜（建议 125 秒）

录屏中清晰显示“真实资料”和“模拟测试”标记。必须实际点击、导入并看到状态变化，不能只是静态页面滚动。优先以 GS-05→GS-06 的**真实风险提示到方案终止**展示状态迁移；如展示否认、更正或过期支线，画面必须标出模拟测试。

| 时间 | 操作画面 | 旁白重点 |
|---|---|---|
| 0–12 秒 | 事件列表，选高新发展（000628）及“华鲲振宇 70% 股权收购”事件 | 研究员要确认这项收购目前进展到哪一步 |
| 12–35 秒 | 打开 GS-01、GS-02 的时间线和原文；展开任一已有材料的四时间栏 | 最初筹划、后来披露预案；发生日、披露日、抓取日各有含义，未知更新时间留空 |
| 35–52 秒 | 将 GS-X1 倍特期货公告拿来比对；若已有可追溯转载，再展示同源分组 | 同公司、同一天也可能是另一件事；转载不能累计为独立证据 |
| 52–83 秒 | 导入 GS-06 原文/节选，展示提取主张、引文和“并入华鲲振宇事件”建议，用户确认 | AI 提建议，用户检查来源与归属；提交的是官方真实材料 |
| 83–105 秒 | 展示 GS-05→GS-06 的状态变化、旧版记录和站内通知 | 2023 年重组方案从“预计难续”变为“已终止”；后续收购意向及时间仍不确定 |
| 105–125 秒 | 展开 GS-06 的四时间栏、打开[公告原文](https://static.cninfo.com.cn/finalpage/2024-04-19/1219675794.PDF)，再展示边界说明 | 董事会于 4 月 18 日决议、4 月 19 日公开披露；终止旧方案不等于永久放弃收购 |

视频末尾可用一屏附上网站 URL、代码仓库、README、测试记录入口。录屏前按上述操作走通一次，准备备用本地录屏；不要在视频里声称未实现的实时抓取、行情验证或模型能力。

## 6. AI 使用与人工验证记录模板

每次 AI 生成或处理关键内容时增一行。代码生成、文案、数据提取与运行时 AI 推理分开记录；没有调用模型的步骤写“规则/人工”，避免含混地称“AI 完成”。不得在记录中写入 API 密钥或私人材料。

| 时间/版本 | 步骤 | 模型/工具及版本 | 输入来源 ID、提示词摘要 | AI 输出与置信/不确定点 | 人工核验方法 | 修正与最终采用内容 | 证据/日志链接 |
|---|---|---|---|---|---|---|---|
| 待填 | 如：主张提取、同事件建议、摘要、代码生成 | 待填 | 待填 | 待填 | 对照公告原句、时间、公司与金额；运行测试 | 待填 | 待填 |

交付前附三类实例：一次 AI 正确抽取、一次 AI 错误/不确定而被人工纠正、一次来源或接口异常触发降级。README 中逐项声明哪些能力已在部署版可操作，哪些仅是方案或离线数据准备。
